PROJECT NOTE / LOCAL AI WORKSPACE

让 16 GiB 电脑
尝试 70B 本地推理

AvaSubaru4862026 年 11 月 14 日项目介绍 · 约 6 分钟阅读

这次我想解决的问题，是怎样把三档模型、推理环境和资源管理装进一个完整工作区，让一台普通 Windows 电脑也能开始本地 AI 实验。

从一台已有的电脑开始

Local AI Workspace 的参考实验设备是 Intel Core i5-1235U、16 GiB 内存和 Intel UHD 核显。面对这样的配置，模型文件放得下，运行时的内存安排却需要仔细设计。

本版 Llama 3.3 70B 的低比特权重文件约 15.85 GB，也就是 14.77 GiB。系统、桌面应用、上下文缓存和计算缓冲还要占用空间。项目因此把重点放在权重怎样读取、哪些内容同时驻留，以及每次任务结束后怎样回收资源。

我将这些流程整合成 Windows 桌面应用：选择模型、输入问题、观察回答与指标，最后导出日志。这样一次使用就能留下可以复查的运行记录。

三档模型，同一个工作区

完整便携包包含三款固定版本的模型，以及 27B 配套视觉组件。模型清单记录了来源、文件大小、量化方式与 SHA-256，方便确认每次实验使用的是哪一份权重。

模型量化权重体积主要用途
Qwen3 8BUD-IQ2_XXS2.61 GB轻量文字交互
Gemma 3 27BUD-IQ1_S6.51 GB文字与图片输入
Llama 3.3 70BUD-IQ1_S15.85 GB大参数本地运行探索

视觉组件另占约 0.86 GB；连同应用与运行环境，完整 ZIP 为 29.70 GB。低比特量化减少权重表示的存储开销，同时也带来精度取舍，后续需要用固定任务继续评估回答质量。

让存储、内存与计算配合起来

SSD保存完整模型权重
→
有限内存安排权重与运行缓冲
→
CPU逐步计算并生成 token

8B 与 27B 的文字路径使用内存映射，按需访问模型文件。70B 使用分层 CPU 读取路径，让当前计算需要的权重进入内存，再推进后续计算。SSD 的读取能力、CPU 和系统负载都会影响等待时间。

应用统一负责启动预算、模型切换、请求取消与子进程回收。70B 的驻留配置上限为 4 GiB，默认模型进程提交上限为 12 GiB。它们是运行参数，实际内存占用需要通过日志观察。

配置文件为 70B 标注了 24 GiB 起、32 GiB 推荐内存；16 GiB 参考机上的短回答属于受限条件实验。运行能力、持续速度和回答质量需要分别验证。

从“能启动”，到“能操作、能记录”

项目的工程工作集中在把已有基础组件连接成完整流程。桌面端提供聊天、历史会话、附件输入和 Python 工作区；运行端组织模型配置、内存预算、文字与视觉路径，并处理切换和退出。

Gemma 3 27B 使用配套视觉组件处理图片。视频通过 FFmpeg 最多抽取 6 帧，再把画面与采样时刻一起交给同一个 27B 模型。目前已有两张简单图片样例通过测试，两次视频回答的完整性仍需改进；视频路径分析抽样画面，不转写音频。

基础模型来自 Qwen、Google Gemma 和 Meta Llama，量化采用 Unsloth 发布版本，推理依赖 llama.cpp 等上游组件。我的工作主要是桌面交互、运行路径组织、资源管理、离线集成与统一日志。

把测试条件和结果一起写下来

下面这组数据来自 2026 年 10 月 29 日答辩材料中的实机演示。参考机为 i5-1235U、16 GiB RAM、Intel 核显，模型串行运行，使用 512-token 上下文、最多生成 64 tokens。输入是“请用不超过20个汉字，介绍本地AI的作用。”

模型输出 tokens解码 token/s首字 / 秒整轮 / 秒
8B164.26113.4817.23
27B121.16337.2347.55
70B100.057153.98330.14

这些数据说明了本次短任务的等待与生成情况。70B 可以在参考机上完成回答，但等待仍然很长。要评价持续输出，需要增加生成长度、重复固定提示，并把冷启动、热启动和系统负载分开记录。

27B 4 token/s、70B 0.5 token/s 是后续优化目标。后续会结合磁盘读取、线程、上下文和内存记录定位瓶颈，再用多轮实验检查改动是否有效。

数据依据随项目提供的 2026-10-29 答辩材料；本次网页发布未重新运行模型测速。10 月 28 日的项目说明保留了另一组更短样本，比较时应使用相同的任务与统计口径。

让每次运行都能留下依据

“导出运行日志 ZIP”会生成 runs.csv、runs.jsonl 和字段说明，记录软件版本、设备信息、模型哈希、量化、token 数、首字时长、解码速度、内存和结束状态。聊天正文和附件保留在本机，不进入该统计包。

比较不同设备时，我会先固定模型哈希、后端版本、提示、线程、上下文和输出长度，再分别观察启动等待、生成速度与资源占用。这样才能判断差异来自设备、参数还是一次偶然的后台负载。

源码、材料与完整便携包

GitHub 仓库整理了应用源码、技术文档、原始 Word 介绍、答辩 PPT / PDF，以及两段演示视频。完整便携包包含模型与运行环境，以 16 个分片保存在 Release 中。

  1. 下载 .part01 至 .part16，以及 manifest.json、SHA256SUMS.txt、Merge-Portable.ps1，放入同一文件夹。
  2. 在 PowerShell 中运行 .\Merge-Portable.ps1，校验分片并还原完整 ZIP。
  3. 将 ZIP 完整解压到 SSD 目录，双击 LocalAIWorkspace.exe，保留原有目录结构。

这是 Windows 桌面应用，本站提供项目介绍与下载入口。模型推理在本机执行，具体体验取决于电脑配置和运行参数。
